# Kyoku

一个用 Rust 编写的日麻牌谱复盘助手。

目前提供桌面 GUI 和命令行。macOS 桌面版可构建包含完整本地推理环境的安装包。

## 安装与启动

桌面安装包适用于 **Apple Silicon（M 系列芯片）、macOS 14 及以上**。
打开 `Kyoku_0.1.0_aarch64.dmg`，将 Kyoku 拖入“应用程序”，然后启动。

安装包已包含本地分析引擎和模型，无需另外安装 Python、下载权重或配置 API Key。
**回放和 Mortal 分析可以离线使用；导入天凤链接和 Agent 问答需要联网。**

当前安装包尚未经过 Apple 公证，首次打开可能被 macOS 拦截。请确认安装包来源可信；
如果系统不允许打开，可以先使用下方的[源码运行方式](#从源码运行)。
暂不提供 Intel Mac、Windows 和 Linux 安装包。

## 开始第一次复盘

### 1. 导入牌谱

点击“导入牌谱”，选择一种来源：

| 来源 | 操作 |
| --- | --- |
| 示例牌谱 | 选择“对局回放”，点击“导入示例”。第一次使用推荐从这里开始。 |
| 本地文件 | 选择天凤 JSON 文件，也可以直接将文件拖入窗口。 |
| 天凤链接 | 粘贴完整牌谱链接或 log ID，点击“导入链接”。 |

本地文件需为四人天凤 JSON（`tenhou.net/6` 格式），最大 16 MiB。
目前不能直接导入三人牌谱、雀魂牌谱、天凤 XML 或 mjai JSONL。

导入后，在顶栏“复盘玩家”中选择自己。天凤链接里的 `tw` 不会自动替你选择玩家。

### 2. 回放牌局

点击左侧牌局可切换局数，用底部进度条定位到想看的位置。
点击播放按钮可自动回放，旁边可以调整播放速度。

| 快捷键 | 操作 |
| --- | --- |
| `←` / `→` | 后退 / 前进一个事件 |
| 空格 | 播放 / 暂停 |

在输入框中打字时，快捷键不会影响回放。牌谱进度中的 `G` 是事件编号，不是巡目；
摸牌、出牌、鸣牌等各自占一个事件。

默认只显示所选玩家的手牌。勾选“显示全部手牌”可查看其他玩家的手牌。
牌河中浅棕色牌底表示摸切，淡化的牌表示已被鸣走，鼠标悬停可查看标记。

### 3. 分析自己的选择

点击“分析此玩家”，等待出现“决策点已就绪”。分析期间可以继续回放。
随后用“上一决策”和“下一决策”跳到该玩家需要作出选择的位置。

右侧“决策分析”会展示 Mortal 的最终推荐、实际动作及候选动作。
**点击候选中的切牌名称**，可以查看对应的有效牌和不可见枚数。

读结果时，可以先看这三项：

| 项目 | 怎么看 |
| --- | --- |
| 最终推荐 | Mortal 在这个局面建议的动作。若与 Q 值排序不同，以最终推荐为准。 |
| 向听与进张 | 比较切牌后的向听数，以及哪些牌能让向听数下降。不可见枚数包含对手暗牌，不等于牌山里还剩多少张。 |
| Q 值 | 用于比较模型对候选动作的评价，不是胜率或预期得点。 |

向听和直接进张相同，不代表后续改良、打点和防守价值也相同。
想核对具体数据，可以展开“原始证据与模型信息”。

同一份牌谱中，已分析玩家的结果会保留到应用关闭。导入新牌谱或重启应用后，需要重新分析。

## 和 Agent 一起复盘

### 配置问答服务

仅使用回放和本地分析时，可以跳过这一节。

打开右上角“设置”，在“Agent 问答”中填写以下内容：

| 设置 | 填写内容 |
| --- | --- |
| 服务地址 | 服务商提供的完整 API 地址，通常以 `/responses` 或 `/chat/completions` 结尾。不能只填网站首页或 `/v1`。 |
| 模型名 | 服务商提供的准确模型名称；模型需要支持工具调用。 |
| API Key | 该服务对应的密钥。本机无需认证的服务可以留空。 |

例如，使用 OpenAI 服务时，地址可填写 `https://api.openai.com/v1/responses`；
使用兼容服务时，填写服务商给出的地址，如 `https://your-service.example/v1/chat/completions`。
示例中的域名和模型占位符必须替换成自己的实际配置。

DeepSeek 官方服务填写 `https://api.deepseek.com/chat/completions`，模型名例如
`deepseek-v4-pro`，密钥使用 DeepSeek 平台创建的 API Key。
模型名称以 [DeepSeek 官方文档](https://api-docs.deepseek.com/zh-cn/) 为准。

先点击“测试连接”，看到成功提示后，再点击“保存设置”。**测试成功不会自动保存。**
连接测试会先请求工具调用，再返回测试结果确认模型能继续回答；不发送牌谱，通常需要两次 API 请求。
连接测试和提问都可能产生服务商的 API 调用费用。失败时会显示服务端提供的脱敏错误说明（如有）。

API Key 保存在 macOS 钥匙串中，保存后输入框留空是正常的。
服务地址不变时，留空会保留原密钥；更换服务地址时，需要重新填写对应密钥。
要移除密钥，勾选“删除已保存的密钥”并保存。
安装包中的问答配置请在这个页面完成，不读取源码目录中的 `.env`。

### 提问与追问

先完成玩家分析，用“下一决策”进入一个决策点，再切换到右侧“一起复盘”。
可以从这个问题开始：

> 比较这里的候选切牌，说明向听、进张和 Mortal 的倾向。

也可以针对当前局面继续问：“为什么推荐切这张？”或“这几个候选的有效牌有什么不同？”
比较两个切牌时，Agent 可以检查切后手牌和进张差异；也可以问“如果随后摸到 4m，
这两种切法各自怎么继续？”。假设分支保持其他玩家和公开牌不变，不是实际后续牌谱。
回答中的“判断”表示基于比较的有条件解释，不代表已经证明 Mortal 的推荐原因或整体最优。
回答会在生成完成后一次显示；单次服务请求最多等待120秒，多工具问题可能需要多次请求。
如果请求失败，问题会保留，可以重试。

同一局面可以连续追问。**每次复盘使用独立会话（session），切换事件、玩家或牌谱不会删除会话。**
在当前牌谱中切回原局面，会恢复原会话和未发送的草稿；点击“新建会话”可以在同一局面另开一次讨论。
回答生成期间可以继续浏览其他局面，结果会保存到原会话；同一个会话需等上一条请求结束后再提问。

提问时，服务会收到问题和当前局面的可见信息、牌效率、Mortal 判断，
不会收到对手暗牌或实际后续动作。“显示全部手牌”不会改变问答使用的信息范围。
遇到证据不足的解释，可以查看原始证据核对，不要把推测当成模型推荐的确定原因。

### 深入比较速度、打点与风险

在“一起复盘”里直接提问即可，Agent 会按问题调用计算工具：

| 想检查什么 | 可以这样问 |
| --- | --- |
| 完整改良 | “这两种切法现在进张相同，请比较所有可能的下一张摸牌，双方各有什么优势？” |
| 役种与打点 | “切这张之后有哪些役种路线？听牌时，各张待牌默听和立直分别多少点？” |
| 防守 | “这几张牌分别对哪家有安全依据？切完还剩几张现物？” |
| 吃碰杠与立直 | “碰与不碰有什么具体区别？碰完能切什么，打点和门前状态如何变化？” |
| 点差目标 | “我要超过玩家1，直击他、荣和别人和自摸分别需要什么打点？” |

完整改良会遍历所有仍有不可见副本的下一张牌，再比较一次切牌；“占优枚数”是分支覆盖统计，
不是摸牌概率或长期收益。默认只返回各分支的最佳指标和候选牌名；追问某张具体摸牌时，
再展开这个分支的全部后续切牌和进张详情。

听牌分析把**完成牌形、有役、舍牌振听和条件打点**分开。打点使用普通非赤和牌张，保留手中已知的赤宝牌，
不猜测未知里宝牌、新宝牌或一发等事件加成；它还没有完成同巡振听、立直后见逃等全部合法性检查。
役种距离不考虑公开牌已经耗尽，也不是完成概率。防守中的筋和壁只作为线索，不换算成放铳率。

吃碰比较会区分赤牌消耗组合，并排除食替切牌；杠的岭上分支只比较牌形，不计未知新宝牌或抢杠风险。
跳过分析会检查见逃后立即产生的振听，区分临时振听与立直后持续振听；限制对整组待牌的荣和生效，不阻止自摸。
原有振听信息不足时会标明未知，不把“没有检查出来”当作“没有振听”；临时振听在后续事件中可能解除。
点差工具计算单人和牌后的条件变化，包含本场、当前立直棒和同点起家顺序；荣和门槛可能不是实际存在的符番档位，
还需要和自家打点对照。它不预测比赛是否结束或最终顺位。

例如，导入示例牌谱并分析玩家0，在事件 `G2` 比较切 `2p` 和 `3m`：先问完整改良，再追问摸到 `4m`。
这个分支中，切 `2p` 后再切东为两向听、28枚直接进张；切 `3m` 的对应最佳直接进张为20枚。
这说明该分支的速度差异；结合其他分支、打点和防守之后，才能讨论更完整的取舍。

### 保存、加载与查看历史会话

已发送的问题、回答和执行轨迹会自动保存到本机，关闭应用后仍可找回。
点击顶栏“历史会话”，选择一次复盘即可查看或继续追问，**无需重新导入牌谱或运行 Mortal**。
历史会话始终使用它建立时的固定局面证据，不会随当前牌桌改变。
未发送的输入草稿只在本次运行中保留。

- **导出 JSON**：选中历史会话后点击“导出 JSON”，文件会保存到系统“下载”目录，界面显示完整路径。
- **加载 JSON**：点击“加载 JSON”选择此前导出的 Kyoku 会话文件（最大 32 MiB）。导入创建独立副本，不覆盖已有会话。
- **查看工作流程**：展开每轮问答下的“工作流程”，可查看模型请求、返回结果、工具名称与参数、工具结果，以及回答校验与失败记录。“会话上下文”展示固定证据和系统提示词。

会话文件保留续聊所需的消息历史、供应商返回的上下文状态、局面证据、服务地址及模型名，
不包含配置中的 API Key，也不附带完整牌谱或对手暗牌。自动保存位置为系统应用数据目录下的 `dev.kyoku.desktop/sessions`；
macOS 通常位于 `~/Library/Application Support/dev.kyoku.desktop/sessions`。
分享前请留意文件中包含你发送的问题和模型回答。

加载和查看历史无需问答服务；继续追问时，设置中的服务地址和模型必须与原会话一致，密钥使用本机当前配置。
修改设置不会删除旧会话。若希望使用另一模型，可以在当前决策点新建会话。
应用版本升级后若提示词不兼容，历史仍可查看和导出，继续问答需新建会话。
请求失败会保留工作流程并提供重试；意外退出时未完成的问题会标为“未完成”，不会自动重新发送。
会话达到容量上限时，请新建会话，已有记录会保留。

## 从源码运行

已有桌面安装包的用户无需执行本节。以下命令除特别说明外，都在仓库根目录运行。

### 准备环境

安装 Git、稳定版 Rust 工具链。运行桌面界面还需要 Node.js 22.12+ 和对应系统的
[Tauri 开发依赖](https://v2.tauri.app/start/prerequisites/)；使用 Mortal 分析需要 Python 3.11+
（推荐 3.12）和 curl。

桌面版已在 macOS 使用；Linux 桌面尚未完成验证，Windows 的 Mortal 环境尚未适配。

```bash
git clone https://github.com/xqqQwQNyanNyan/kyoku.git
cd kyoku
```

先回放一份自带牌谱，确认能够运行：

```bash
cargo run --bin replay -- fixtures/tenhou/ranked_game.json
```

看到逐事件的局面变化和结束摘要，即可继续。只使用命令行回放，不需要安装 Python 或 Node.js。

### 准备本地分析并启动桌面界面

```bash
bash scripts/setup-mortal.sh python3.12
```

如果本机 Python 命令不是 `python3.12`，替换为实际命令或可执行文件的绝对路径。
首次准备需要联网下载依赖和约 125 MiB 的权重；末尾出现 `Mortal checkpoint verified`
和 `Ready` 后，运行一次分析：

```bash
cargo run --bin review -- --player 0 --event 2 fixtures/tenhou/ranked_game.json
```

看到局面、Mortal 推荐及候选切牌后，启动桌面界面：

```bash
npm --prefix desktop ci
npm --prefix desktop run tauri dev
```

之后按上面的桌面步骤导入牌谱、选择玩家和分析。问答服务同样可以在“设置”中配置。
退出时关闭窗口，并在终端按 `Ctrl+C`。不要用 `npm run dev` 代替上述启动命令，它只启动前端页面。

如果只想使用桌面回放，可以跳过本地分析的准备步骤。

## 命令行使用

下面的 `fixtures/tenhou/ranked_game.json` 可以换成自己的本地 JSON 路径；路径含空格时请加引号。
`--player 0` 表示牌谱玩家列表中的第一位，`1`、`2`、`3` 依次对应其余玩家，不随每局座风改变。
`--event 2` 表示全场编号为 2 的事件应用后的局面，不是第二巡。

### 回放与分析

```bash
# 回放整份牌谱。
cargo run --bin replay -- fixtures/tenhou/ranked_game.json

# 查看指定事件后的完整局面。
cargo run --bin replay -- --state-at 120 fixtures/tenhou/ranked_game.json

# 列出玩家 0 的整场决策、实际动作和推荐。
cargo run --bin review -- --player 0 fixtures/tenhou/ranked_game.json

# 查看一个决策点的局面、牌效率和 Mortal 判断。
cargo run --bin review -- --player 0 --event 2 fixtures/tenhou/ranked_game.json
```

先用整场决策列表找到事件编号，再用 `--event` 查看细节。
只想看模型判断时，将 `review` 换成 `mortal`。

`replay` 也接受天凤链接或 log ID：

```bash
cargo run --bin replay -- 'https://tenhou.net/0/?log=<log-id>'
```

将 `<log-id>` 换成实际编号。`review`、`mortal` 和 `agent` 需要本地 JSON，
不能直接使用链接。已有链接时，可以先下载：

```bash
curl -fL --referer 'https://tenhou.net/' \
  'https://tenhou.net/5/mjlog2json.cgi?<log-id>' -o /tmp/kyoku-game.json
cargo run --bin review -- --player 0 /tmp/kyoku-game.json
```

### 配置命令行问答

第一次配置时，在仓库根目录执行；已有 `.env` 则直接编辑，避免覆盖原配置：

```bash
cp .env.example .env
```

使用兼容服务时，填写完整地址、模型名和该服务的密钥：

```dotenv
KYOKU_OPENAI_ENDPOINT='https://your-service.example/v1/chat/completions'
OPENAI_MODEL='your-model-name'
AGENT_API_KEY='your-key'
```

使用 OpenAI 默认服务时，删除或注释 `KYOKU_OPENAI_ENDPOINT` 和 `AGENT_API_KEY`，改为：

```dotenv
OPENAI_MODEL='your-model-name'
OPENAI_API_KEY='your-key'
```

占位符必须换成实际值。密钥用单引号包裹，不要把 `.env` 分享或提交到仓库。
程序优先使用命令行参数，其次是终端已有环境变量，最后才是 `.env`。
显式配置服务地址时只使用 `AGENT_API_KEY`，不会回退到 `OPENAI_API_KEY`。

### 提问与整场浏览

```bash
# 提问一次，回答后退出。
cargo run --bin agent -- --player 0 --event 2 \
  --question '比较这里的候选切牌，说明向听、进张和 Mortal 的倾向。' \
  fixtures/tenhou/ranked_game.json

# 在同一局面连续问答。
cargo run --bin agent -- --player 0 --event 2 fixtures/tenhou/ranked_game.json

# 分析整场，然后选择决策点并提问。
cargo run --bin agent -- --player 0 --browse fixtures/tenhou/ranked_game.json
```

交互模式下直接输入问题并回车。以下命令用于浏览和退出：

| 命令 | 用途 |
| --- | --- |
| `/evidence` | 查看当前局面的原始证据，无需配置问答服务。 |
| `/quit` | 退出。 |
| `/list` | 列出整场决策，仅浏览模式。 |
| `/select N` | 跳到事件编号 N 的决策，仅浏览模式。 |
| `/next`、`/prev` | 切换相邻决策，仅浏览模式。 |
| `/show` | 重看当前局面和分析，仅浏览模式。 |

没有安装 Mortal 时，可以在单局面问答命令中加 `--without-mortal`，只询问可见局面。
这时不会提供切牌效率或模型推荐，也不能同时使用 `--browse`。

需要更多参数时，运行 `cargo run --bin replay -- --help`；其他命令同样支持 `--help`。
`--llm-model` 指定问答模型；`--model` 指定 Mortal 权重文件，不要混用。

## 常见问题

| 遇到的问题 | 处理方式 |
| --- | --- |
| 天凤链接导入失败 | 检查链接或 log ID 是否完整、牌谱是否仍可访问，也可以改用本地 JSON。想先体验功能时，选择内置示例。 |
| 桌面版提示引擎不可用 | 打开“设置”，点击“检查引擎”。安装包用户请确认使用包含模型的完整安装包；源码用户先完成 `setup-mortal.sh`。 |
| 没有推荐，或无法提问 | 确认选中了正确玩家并完成分析，再用“下一决策”跳到该玩家的决策点。 |
| 问答提示认证或模型错误 | 核对完整服务地址、模型名和对应密钥，确认模型支持工具调用，重新测试连接并保存。CLI 用户还需检查终端环境变量是否覆盖了 `.env`。 |
| 连接测试提示 HTTP 400 或 422 | 先看提示中的服务端错误码、参数和说明，判断模型名或请求参数哪里不兼容；400 本身不能确定是密钥或余额问题。 |
| 提问超时或回答校验失败 | 保留当前局面重试；持续失败时，检查服务是否可用，或换用支持工具调用的模型。回放和本地分析仍可使用。 |
| CLI 找不到牌谱或模型 | 在仓库根目录运行命令，或改用绝对路径。`--python`、`--runtime`、`--model` 可分别指定 Python、Mortal 目录和权重文件。 |
| 移动源码目录后无法分析 | Python 虚拟环境可能仍指向旧路径，需要在新位置重新创建。若设置过 `KYOKU_HOME`，也要更新为正确的资源根目录。 |
