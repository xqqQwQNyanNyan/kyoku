# Mahjong Assistant

一个面向麻将牌谱复盘与局面分析的智能助手。项目首先尝试把可验证的麻将算法、Mortal 的打法判断和大语言模型的工具编排能力组合起来，为用户提供可以继续追问的分析结果。书籍、历史牌谱和统计数据属于后续可选的增强能力。

> 当前状态：项目初始化阶段。仓库目前只有最小 Rust 可执行程序，下面的内容是实现目标与架构约定，不代表相关功能已经完成。

## 产品目标

用户可以导入牌谱或输入一个局面，然后用自然语言提问，例如：

- 这一巡为什么不应该切六万？
- Mortal 的推荐与牌效率算法为什么不同？
- 整场牌谱中最值得复盘的三次决策是什么？
- 有没有书籍观点或历史局面支持这个判断？

系统返回的不只是结论，还应标明结论来自确定性计算、Mortal、历史统计、书籍资料，还是 LLM 的综合推断。

## 架构

```text
用户 / GUI
    |
    v
LLM 编排层
    |-- 调用 Rust 牌谱与算法工具
    |-- 调用 Mortal 推理服务
    |-- [可选] 检索书籍知识库
    `-- [可选] 查询历史牌谱与统计数据
    |
    v
带来源、证据和置信说明的分析结果
```

### Rust 核心

Rust 负责必须准确、稳定和可测试的部分：

- GUI 后端与应用核心逻辑；
- 不同来源牌谱的解析与规范化；
- 牌局状态重建、动作合法性和规则校验；
- 向听数、有效牌、牌效率、打点、符数和危险度等算法；
- 统一的工具输入输出类型；
- Mortal、LLM、存储层和界面之间的适配。

核心规则与算法不得依赖 LLM 猜测。相同版本、相同规则和相同输入必须得到可复现的结果。

### Mortal

Mortal 作为外部的打法顾问工具使用。它提供候选动作、动作分布或局面价值等模型判断，但不作为规则正确性的唯一来源。

每次调用应记录：

- Mortal 与模型版本；
- 规则和推理配置；
- 规范化后的输入；
- 原始输出与解析后的输出；
- 耗时、错误和降级情况。

### LLM

LLM 负责理解用户意图、选择工具、综合证据和生成解释。它不应独立计算向听数、点数、剩余牌数或动作合法性。

输出应尽可能区分以下来源：

- `calculation`：Rust 确定性计算；
- `mortal`：Mortal 模型判断；
- `statistics`：历史牌谱统计；
- `reference`：书籍或文章知识；
- `inference`：LLM 基于以上信息进行的推断。

### 知识与数据

书籍、规则说明、战术文章和人工复盘适合进入语义知识库，用于带引用的检索增强生成。

牌谱不应只作为普通文本放进向量库。计划按以下层次保存：

1. 原始牌谱：保留来源文件、哈希、规则和解析版本；
2. 规范化数据：按对局、局、巡目、动作和局面建模；
3. 分析数据：保存特征、标签、统计指标和模型输出；
4. 语义案例：把有代表性的局面和人工复盘放入知识库。

相似局面检索应优先使用结构化特征，再由语义检索和 LLM 负责解释。

### 离线统计与训练

统计分析和模型训练是两条不同的工作流：

- 统计管线从清洗后的牌谱直接聚合事实指标；
- 训练管线基于版本化的数据集学习预测或决策模型；
- 评估管线在固定测试集上比较算法、Mortal 和自研模型。

在数据定义、基线和评估方法稳定之前，不急于训练自有模型。

## 建议的代码布局

随着功能增加，项目可以演进为 Cargo workspace：

```text
mahjong-assistant/
├── crates/
│   ├── mahjong-core/       # 牌、规则、局面和动作等领域模型
│   ├── paipu/              # 各来源牌谱解析与规范化
│   ├── analysis/           # 确定性麻将算法
│   ├── mortal-client/      # Mortal 接口与协议适配
│   ├── knowledge/          # 知识检索与引用类型
│   ├── orchestration/      # LLM 工具定义和编排
│   └── storage/            # 原始牌谱、结构化数据与缓存
├── apps/
│   ├── desktop/            # GUI 应用
│   └── cli/                # 调试、导入和批处理入口
├── fixtures/               # 小型、可公开的测试牌谱
└── docs/                   # 架构决策、数据格式和规则说明
```

该目录只是目标形态。引入 workspace 前，优先完成一条可以端到端运行的最小链路，避免过早拆分 crate。

## MVP 路线

1. 明确第一种麻将规则和第一种牌谱格式；
2. 完成牌谱解析、状态重放和基础合法性校验；
3. 实现并测试向听数、有效牌等基础算法；
4. 封装 Mortal 调用，保存可复现的推理记录；
5. 让 Agent 能针对单个局面调用工具并回答追问；
6. 提供最小可用的牌谱复盘界面。

完成以上闭环就可以视为 MVP。以下内容属于可选增强，不影响核心项目是否完成：

- 整场牌谱中的关键决策筛选；
- 带引用的麻将书知识检索；
- 历史牌谱检索与统计分析；
- 自有数据集、离线评估和模型训练。

## 本地运行

安装稳定版 Rust 工具链后执行：

```bash
cargo run
cargo test
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
```

目前 `cargo run` 只会输出 Cargo 生成的占位内容。
