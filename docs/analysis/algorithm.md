# 候选事实计算：实现与性能

当前目标见 [分析设计](design.md)：覆盖17项因素的事实和条件后果，综合动作偏好由Mortal提供。这里不进行整局搜索、暗手抽样、概率训练或尾部价值估计。

## 1. 调用与模块

`compare_discard_facts(first, second, draw)` 读取一次校验后的快照，共用公开局况与安全依据，对两个已提供切牌分别计算事实。`draw=null` 给出根候选及一向听到听事实；指定普通牌时展开该次摸牌后的所有切牌。

| 模块 | 职责 |
| --- | --- |
| `src/analysis/shanten.rs`、`yaku/distance.rs` | 普通／特殊型、目标役的牌形与数量约束求解。 |
| `src/analysis/route_facts.rs` | 结构距离、已知牌数距离、一次推进牌与保留推进的切牌。 |
| `src/analysis/hand_structure.rs` | 局部组合、两组同时使用时的用牌冲突及孤立牌种。 |
| `src/analysis/tile_efficiency.rs`、`discard_comparison.rs` | 牌效率及一次比较内的向听缓存。 |
| `src/analysis/winning_value.rs`、`score_scenario.rs` | 具体成手支付、单人和牌和荒牌流局的条件结算。 |
| `src/agent/strategy/facts.rs` | 组织双方事实、公开局况、指定摸切及一向听到听明细。 |
| `src/agent/strategy/hand.rs`、`defense.rs`、`actions.rs`、`scores.rs` | 复用原有手牌、分家安全、动作和点差工具，接入路线推进和条件支付。 |

聚焦查询包括 `analyze_yaku_route`、`analyze_hand`、`analyze_defense`、`analyze_actions`、`analyze_score_targets`，以及给定条件的 `analyze_draw_outcomes`、`analyze_win_outcome`。牌效率专用的 `compare_discards` 和 `compare_improvements` 保留原接口与指标含义。

## 2. 已知牌数约束

先校验自家暗牌、副露和公开牌的实体张数。对暗牌目标中的每个牌种，设置上限：

```text
目标暗牌可用上限 = 当前暗牌张数 + 未见张数
```

未见池已经排除固定副露、弃牌和指示牌。普通型DP的每种牌需求不得超过上限；七对子只能选择尚能供应两张的牌种；国士必须能供应全部十三种幺九及至少一个对子。固定面子仍按原役种约束参与计算。

这个上限只表达数量约束，不能证明未知牌在活牌山里，也不处理对手竞争和获得这些牌的概率。当前手牌不能满足指定役时返回不可达；未支持的役种返回错误，二者不混淆。

一次推进先检查摸牌后的目标距离是否降低，再枚举真正能保留降低结果的切牌。摸入牌使未见池减少一张；随后切出的牌仍然已知，目标上限也减少一张。不能把原根状态的可用池直接用于整个后续链条。

混一色严格要求一种数牌花色加字牌，普通型和七对子两种完成形均检查；清一色和字一色不能替代混一色。当前混一色／清一色距离取各花色中的最小值，不能据此断言某个指定花色的距离。

## 3. 等待、动作和结算

原手牌报告计算已听牌的待牌、拆分、役、符番与支付。统一比较对一向听的各可用进张枚举到听切牌，并调用相同计分能力。指定摸牌的详细比较不按受入筛掉其他切牌，其路线和库存保持独立。

假设分支记录此前切出的牌，舍牌振听对整组待牌生效；安全库存对已受理立直者可以使用假设已通过的根切牌，该依据明确标为假设。后续等待计分不引入新的立直、一发、未知里宝牌或新宝牌；历史荣和限制仍以实际检查范围为准。

自家普通完成形可以给出具体基础支付及条件结算。新立直分支先扣除1000点、增加供托，再结算；输出净点差统一相对原快照。已受理的立直不再扣款；尚未受理的宣言按明确受理条件处理。

吃碰与过牌通过 `call_comparison` 并列同一快照的手牌结构、各合法吃碰后切牌的向听、门前状态、实际暗牌张数和分家现物库存。摘要来自已计算的完整分支，不选择总体最优动作。防守报告另给出 `riichi_blocked_by_open_melds`：吃碰和明杠阻止立直，暗杠不破坏门前；false只表示没有这项阻碍，不表示满足立直的其他条件。相同的某家现物库存不能推出总体防守代价相同。

`analyze_win_outcome` 的赢家、付款者、符与总番是输入条件，不从对手公开面子猜出来。`analyze_draw_outcomes` 枚举16种听牌组合，普通荒牌流局的罚符总和为零，供托结转；未确定的终局规则不应用。

## 4. 性能

役种的静态转移表按需初始化并复用。普通型DP只依赖上一牌种，存储改为相邻两层，避免反复分配35层表。原有普通型、特殊型及21种役种测试继续验证一致性。

二杯口的四个面子必为两对顺子，因此直接枚举231种顺子对组合及雀头，计算目标缺牌数，避免对每个组合重复运行通用DP。回归测试以原通用约束求解器为参照，同时核验结构距离与数量上限距离。

一次牌效率比较使用局部缓存，键为忽略赤牌差异的暗牌计数及固定副露。缓存只保存牌形向听，不保存分支未见枚数、振听或计分。切牌身份与实际赤牌支付保持独立；缓存随本次比较释放。

基础事实只为当前候选计算。特定役种的推进由聚焦查询展开，常规报告不做全部役种的全部摸切交叉；一向听只自动展开到听事实，其他阶段可指定摸牌查询。详细事实保留全部指定分支切牌，不能通过删除高打点或防守方向提速。

性能测试必须覆盖完整工具调用和结果大小，不以单个向听函数代表交互耗时。手动测量入口：

```bash
cargo test --release --lib agent::strategy::facts::tests::benchmark_fact_comparisons -- --ignored --exact --nocapture
cargo test --release --lib agent::strategy::facts::tests::benchmark_yaku_progression -- --ignored --exact --nocapture
```

运行时间只是当前机器、构建和固定样例下的测量，不作为任意牌形的延迟保证。测试不含Mortal推理、LLM请求和界面渲染。

2026-09-07 本机 release 测量（两个基准串行运行）：基础双候选事实比较7.08ms，一向听自动展开23.76ms，指定摸牌完整展开117.75ms，均为5次完整调用的中位数；三个样例的结果均小于256KiB。复杂役种单次推进查询：混一色107.96ms、一杯口167.31ms、二杯口28.48ms。二杯口改写前同样例约1842ms；该对照只用于解释这项优化，不代表其他役种或全部牌形的加速比。

## 5. 真实牌谱验收与问答边界

手动验收入口在 `src/agent/live_replay_tests.rs`。`replay_fact_sweep` 从本地牌谱目录选取局面扫描完整比较；`replay_selected_facts` 对保存的实战可见快照执行指定工具；`live_replay_fact_comparisons` 使用实际Mortal与已配置LLM连续问答，保存工具、回答和耗时记录。这些测试默认忽略，真实牌谱和调用记录保存在本地，不进入普通测试或提交内容。

2026-09-07 扫描20场公开凤凰桌牌谱、60个局面，共120次比较成功。最终扫描的根候选比较中位数7.19ms，指定摸牌展开中位数86.34ms，最大结果221400字节。另对5个重点局面核验15项具体关系，包括无役听牌、后续不同待牌支付、三枚可见白的单骑可能、南四宝牌等待，以及保听的条件流局收入。这些样例没有统计代表性；工具成功返回也不等于已经验证了自然语言解释。

旧版实际问答暴露了重复调用、输出额度耗尽、结构与引用反复纠错，以及正文扩展超过证据的问题。官方DeepSeek V4 Flash的5个重点局面首问中，1个通过格式与引用校验、3个校验失败、1个输出截断，耗时62至99秒。通过的南四回答仍把条件打点写成上限，并推导出未经验证的后续翻盘方式，说明严格引用校验也不能证明解释正确。

当前已删除答案JSON协议及其引用校验、路径修复、段落数量和排版限制，模型直接返回中文或Markdown；不再因回答格式发起纠错请求。不再拼装仅供引用校验使用的历史事实副本。工具输入、可见信息边界、HTTP与响应协议检查继续保留；`OutputLimit`仍区分明确截断，失败轮次不进入有效历史。宝牌名称与计分共用同一循环规则，保留在工具结果中供模型读取。

前问失败时不会进入会话历史，依赖“刚才两种切法”的追问因而失去比较对象。手动测试现已在前问失败时停止该局面的后续问题；旧记录中这些追问不计入验收，避免把比较错对象的回答计为成功。

早期实验中，DeepSeek官方V4 Flash/Pro关闭思考，输出额度为4096，不使用强制JSON输出模式。官方Chat接口设置 `thinking.type=disabled` 与 `max_tokens`；官方Responses设置 `reasoning.effort=none` 与 `max_output_tokens`。发回旧消息时省去思考字段，本地轨迹仍保留原始响应。其他兼容地址不自动套用关闭思考参数。当前 Agent 的单次输出上限默认16384，思考模式默认沿用服务端行为，可通过模型参数调整。参数含义见 [DeepSeek API说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

传输层将同结构记录按columns/rows制表，相同字段放在common；row_keys保留对象键，没有row_keys则保留数组顺序。只采用比原记录更短的表示，保留全部字段、候选、重复行及null/false/空数组区别；原始证据和会话存档不改变结构。压缩后逐字段还原与原始实战工具结果对照，不能把字节下降当作token或费用同比下降。提示词合并重复工具说明，并要求围绕当前问题作简短回答。关闭思考和改变输入表示后的真实回答质量、实际耗时尚未付费验证。

删除答案校验后，用相同模型重跑上述五个独立首问：四个返回正文，一个因输出额度耗尽失败；没有格式或引用校验，也没有纠错重试。五个局面分别耗时62.82、43.19、83.85、73.84、52.50秒，模型请求数为2、2、3、2、2，包含工具结果回传。两次采样不能用来证明固定提速比例，正文仍出现推论过度，尚不能声称解释质量已通过验收。
